# آموزش به بیمار

نمونه تعاملی فارسی و راست‌به‌چپ برای آموزش بیمار، با رابط واکنش‌گرا برای موبایل و تبلت. طراحی از تصویر مرجع ارائه‌شده الهام گرفته است و صفحات و کنترل‌ها کد واقعی هستند، نه تصویر ثابت.

## اجرا و آزمون

نیازمند Node.js نسخه ۲۰.۱۹ یا جدیدتر (یا ۲۲.۱۲ به بالا):

```bash
npm ci
npm run dev
npm run build
```

برای اجرای آزمون‌های رابط کاربری (پس از نصب مرورگر Playwright):

```bash
npx playwright install chromium
npm run test:ui
```

## صفحات و تعاملات

- صفحه خوش‌آمدگویی برای اولین اجرا، خانه، منو و ناوبری پایین، جستجوی بیماری‌ها و تب‌های جزئیات هر بیماری
- دسته‌های دیابت، قلب، فشار خون، تنفسی و گوارش؛ صفحه آموزش تصویری و پخش ویدیوی نمونه بدون صدا (این ویدیو محتوای آموزشی بالینی ندارد)
- ورود/ثبت‌نام نمایشی با شماره موبایل، ویرایش پروفایل و ذخیره محلی
- افزودن و حذف دارو، فعال/غیرفعال‌سازی برنامه و ثبت مصرف روزانه
- فرم و فهرست درخواست پرستاری، بدون ارسال به ارائه‌دهنده
- QR صفحه هر بیماری در نسخه وب؛ در نسخه آفلاین اندروید، QR فقط نام برنامه و بیماری را به صورت متن نشان می‌دهد و لینک آموزشی نیست
- پنل نمایشی برای افزودن محتوای متنی و تصویر یا ویدیوی محلی (تا ۱.۵ مگابایت برای هر فایل)

داده‌ها و عکس‌ها نمونه هستند. اطلاعات آموزشی باید پیش از هرگونه استفاده واقعی به تأیید متخصص برسد. داده‌های افزوده‌شده صرفاً در localStorage همان دستگاه ذخیره می‌شوند؛ پاک‌کردن داده‌های مرورگر یا حذف برنامه می‌تواند آنها را پاک کند. اطلاعات واقعی و حساس بیمار را وارد نکنید.

## محدودیت‌های ضروری

این پروژه **نسخه نمایشی UI/UX است، نه سامانه پزشکی عملیاتی**. ورود، تأیید هویت و پیامک واقعی وجود ندارد؛ درخواست پرستاری به کسی ارسال نمی‌شود؛ پنل مدیریت احراز هویت ندارد. داده‌ها بین دستگاه‌ها همگام نمی‌شوند و فایل‌های محلی از طریق QR منتقل نمی‌شوند. اعلان مرورگر برای داروهای غیرنمونه صرفاً با اجازه کاربر و تا زمان باز بودن صفحه کار می‌کند؛ در APK یادآور خودکار فعال نیست. در هر دو حالت برای مصرف دارو از آلارم مستقل گوشی استفاده کنید.

برای استفاده واقعی به سرور امن، احراز هویت و پیامک، سطح دسترسی مدیر، ذخیره و پشتیبان‌گیری امن، اتصال به ارائه‌دهنده پرستاری، یادآور قابل اتکا در پس‌زمینه، رضایت و حفاظت از داده‌های سلامت، بازبینی بالینی محتوا، آزمون امنیتی و تأییدیه‌های لازم نیاز است.

## PWA و APK آزمایشی

نسخه وب پس از انتشار روی HTTPS در مرورگرهای سازگار قابل نصب است. از گزینه «نصب برنامه روی دستگاه» در منو استفاده کنید؛ در iOS از Safari، Share و Add to Home Screen را انتخاب کنید. پس از بارگذاری موفق اولیه، فایل‌های برنامه برای استفاده آفلاین ذخیره می‌شوند.

فایل `releases/hamrah-salamat-demo.apk` یک بسته امضاشده **آزمایشی** برای Android 7 به بالا است که رابط وب را در WebView اجرا می‌کند. داده‌های آن جدا از نسخه مرورگر است. نصب ممکن است نیاز به اجازه نصب از منابع ناشناس داشته باشد. روی دستگاه واقعی در این محیط آزمایش نشده و مناسب انتشار یا استفاده درمانی نیست.

### ساخت APK آزمایشی

نیازمندی‌ها: Java 17 یا جدیدتر همراه `javac` و `keytool`، Android SDK platform API 34 یا جدیدتر و Android SDK build-tools شامل `aapt2`, `zipalign`, `lib/d8.jar`, `lib/apksigner.jar`، و ابزار `zip`.

```bash
npm ci
export JAVA_HOME=/path/to/jdk
export ANDROID_JAR=/path/to/android-sdk/platforms/android-35/android.jar
export ANDROID_BUILD_TOOLS=/path/to/android-sdk/build-tools/VERSION
./scripts/build-android.sh
```

در صورت استفاده از Eclipse Java Compiler به جای `javac`، مسیر آن را در `ECJ_JAR` تنظیم کنید. اسکریپت کلید آزمایشی `android/demo.keystore` را می‌سازد که در Git ذخیره نمی‌شود. با امضای متفاوت، نصب روی نسخه قبلی ممکن است نیازمند حذف آن و از دست رفتن داده‌های محلی باشد. برای انتشار واقعی، کلید امن اختصاصی و فرایند امضای تولید لازم است.

پس از ساخت APK، `python3 scripts/preview-mobile.py` رابط موجود در بسته را در قاب گوشی روی پورت ۸۰۰۱ نمایش می‌دهد. این پیش‌نمایش مرورگری است و خود APK یا ویژگی‌های خاص اندروید را اجرا نمی‌کند.
