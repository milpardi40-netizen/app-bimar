# همراه سلامت

نمونه اولیه فارسی و راست‌به‌چپ برای آموزش بیمار، ثبت دارو و درخواست مراقبت در منزل.

## اجرا

نیازمند Node.js نسخه ۲۰.۱۹ یا جدیدتر (یا ۲۲.۱۲ به بالا) است.

```bash
npm ci
npm run dev
```

برای ساخت نسخه انتشار: `npm run build` و برای مشاهده آن: `npm run preview`.

## امکانات نمونه

- پیشخوان واکنش‌گرا و کتابخانه آموزشی با جستجو، دسته بیماری و صفحه جزئیات
- کد QR برای آدرس هر دسته آموزشی
- ثبت محلی اطلاعات بیمار و داروهای روزانه، ثبت مصرف و حذف دارو
- اعلان مرورگر برای داروهای ثبت‌شده توسط کاربر، با اجازه کاربر و فقط هنگامی که صفحه باز است
- ثبت محلی درخواست خدمات پرستاری
- افزودن متن و تصویر یا ویدیو به محتوای هر دسته، با سقف ۱.۵ مگابایت برای هر فایل

## محدودیت‌های مهم

این پروژه **نمونه نمایشی، نه سامانه عملیاتی پزشکی** است. داده‌ها فقط در localStorage مرورگر فعلی ذخیره می‌شوند و با پاک‌کردن داده مرورگر از بین می‌روند؛ اطلاعات محرمانه یا واقعی بیمار وارد نکنید. ورود با موبایل صرفاً ظاهری است و پیامک یا تأیید هویت ندارد. پنل مدیریت بدون کنترل دسترسی است، فایل‌ها و درخواست‌های پرستاری روی سرور ذخیره یا به کسی ارسال نمی‌شوند، و محتوای اضافه‌شده از طریق QR به دستگاه دیگر منتقل نمی‌شود. اعلان مرورگر جایگزین آلارم قابل اطمینان گوشی نیست و در حالت بسته بودن صفحه اجرا نمی‌شود. دو داروی پیش‌فرض فقط نمونه هستند و توصیه درمانی نیستند.

پیش از استفاده واقعی به بک‌اند امن، پایگاه داده و پشتیبان‌گیری، احراز هویت پیامکی واقعی، مجوزهای مدیر، انتقال و ذخیره‌سازی امن فایل، اتصال به ارائه‌دهنده خدمات پرستاری، یادآور قابل اتکا در پس‌زمینه، رضایت و حفاظت از داده‌های سلامت، بازبینی بالینی محتوا، ارزیابی امنیت و اخذ مجوزها و تأییدیه‌های لازم نیاز است. این مخزن ادعای تأیید دانشگاه یا همکاری با شرکت خاصی ندارد. برای انتخاب پیمانکار، سابقه بیمارستانی و مستندات تأییدیه باید مستقلاً بررسی شوند.

## نصب به‌عنوان برنامه (PWA)

پس از انتشار نسخه build روی یک دامنه HTTPS، برنامه را در مرورگر باز کنید و «نصب برنامه» را انتخاب کنید. در اندروید و مرورگرهای سازگار می‌توان از منوی مرورگر نیز گزینه Install app یا Add to Home screen را انتخاب کرد. در iPhone و iPad در Safari از Share و سپس Add to Home Screen استفاده کنید. نصب‌پذیری و ظاهر گزینه‌ها به دستگاه و مرورگر بستگی دارد. برای آزمایش محلی می‌توان از `npm run build` و سپس `npm run preview` روی localhost استفاده کرد؛ سرویس‌ورکر در حالت توسعه فعال نیست.

پس از بارگذاری موفق اولیه، فایل‌های رابط برنامه برای استفاده آفلاین ذخیره می‌شوند. داده‌ها همچنان محلی هستند و با مرورگر یا دستگاه دیگر همگام نمی‌شوند. این نصب، APK مستقل یا انتشار در فروشگاه نیست و یادآوری قابل اتکا در پس‌زمینه فراهم نمی‌کند. پاک‌کردن داده‌های سایت یا حذف برنامه ممکن است داده‌های محلی را از بین ببرد.

## نسخه اندروید آزمایشی (APK)

فایل `releases/hamrah-salamat-demo.apk` یک بسته اندروید امضاشده برای **آزمایش** است، نه نسخه آماده انتشار یا تأییدشده پزشکی. برنامه رابط وب را همراه خود در WebView اجرا می‌کند و به Android 7 (API 24) یا بالاتر و Android System WebView سازگار نیاز دارد. نصب آن ممکن است نیازمند اجازه نصب از منبع ناشناس باشد. داده‌های APK جدا از داده‌های نسخه مرورگر و فقط روی همان دستگاه هستند؛ حذف برنامه می‌تواند آن‌ها را پاک کند. اعلان و آلارم دارو در APK فعال نیست: برای دارو از آلارم مستقل گوشی استفاده کنید. پیامک، حساب واقعی، سرور و ارسال درخواست پرستاری نیز فعال نیستند؛ QR قابل اشتراک در نسخه آفلاین غیرفعال است. APK روی دستگاه واقعی در این محیط آزمایش نشده است.

### ساخت APK آزمایشی

نیازمندی‌ها: Node.js، Java 17 یا جدیدتر همراه `javac` و `keytool`، Android SDK platform API 34 یا جدیدتر و Android SDK build-tools شامل `aapt2`, `zipalign`, `lib/d8.jar`, `lib/apksigner.jar` و ابزار `zip`. اگر به جای javac از Eclipse Java Compiler استفاده می‌کنید، مسیر آن را در `ECJ_JAR` تنظیم کنید.

```bash
npm ci
export JAVA_HOME=/path/to/jdk
export ANDROID_JAR=/path/to/android-sdk/platforms/android-35/android.jar
export ANDROID_BUILD_TOOLS=/path/to/android-sdk/build-tools/VERSION
./scripts/build-android.sh
```

اسکریپت یک کلید آزمایشی محلی در `android/demo.keystore` می‌سازد که در Git ذخیره نمی‌شود. کلید نسخه نمونه تولیدشده به مخزن اضافه نشده است؛ بنابراین خروجی ساخت مجدد ممکن است امضای متفاوتی داشته باشد و برای نصب آن لازم باشد نسخه قبلی را حذف کنید (با حذف، داده محلی از بین می‌رود). برای انتشار واقعی، کلید انتشار اختصاصی و امن، فرایند امضای مناسب، بررسی امنیتی، آزمون روی دستگاه و پیاده‌سازی خدمات واقعی ضروری است. از کلید آزمایشی برای انتشار استفاده نکنید.
